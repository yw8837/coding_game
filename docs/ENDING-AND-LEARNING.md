# 학습과 엔딩 설계 — 0.10 RC

목표는 명령어를 외워 통과하는 것이 아니라, 문제를 보고 값을 바꾸며 **입력 → 코드/설정 → 결과**의 관계를 익히는 것이다. 플레이어가 마지막에 얻는 결과물은 자신이 이름 붙인 작은 프로그램의 배포 기록이다.

| 구간 | 플레이어 행동 | 보이는 결과 | 익히는 개념 |
| --- | --- | --- | --- |
| 간판 | 가게 이름 선택 | 같은 파일의 h1과 간판 변경 | 화면의 글자는 소스의 값 |
| 메뉴판 | 너비 선택 | 휴대폰 안으로 메뉴가 들어옴 | CSS, 고정 크기와 비율 |
| 계산대 | 연산자 한 글자 | 여러 손님 주문의 합계 | 변수·곱셈·같은 규칙의 재사용 |
| 주문함 | 주소·boolean 입력 | 메뉴 응답과 주문 기록 | 주소 일치, 요청·응답, 보관 |
| 첫 6개 의뢰 | 선택으로 한 값 변경 | 기대 결과와 현재 결과 비교 | JSON/CSV/HTML의 작은 데이터 수정 |
| 다음 6개 의뢰 | 빈칸 값 입력 | 경계값·정렬·폭 등 결과 | 입력 형식과 여러 사례 확인 |
| 마지막 6개 의뢰 | JSON 속성 등 짧은 코드 조각 | 주소·로그·날짜·합계 | 실제 문법으로 작은 수정 |
| 내 첫 배포 | 4개 개념 재사용, 이름 자유 입력 | 직접 사용하는 동네 도움판 | 수정·검사·버전·배포의 순서 |

새 형식에는 한 부분씩 안내하고 힌트를 다시 열 수 있게 한다. 전체 답안을 한 번에 적용하는 완료 버튼은 없다. 준비와 전달의 반복 명령은 기본 모드에서 묶지만 실제 명령 엔진과 검사 경계를 통과한다. 숙련자는 설정에서 직접 작업을 선택하고 같은 파일을 터미널과 에디터로 다룬다.

진행은 UI의 완료 표시가 아니라 저장된 파일·검사·API 결과에서 계산한다. 임시 입력 초안·힌트 펼침 여부가 학습 성취의 증거는 아니다. 잘못된 입력에 결과를 보여 주고 다시 시도하게 한다. 힌트 사용량은 보상이나 엔딩 조건에 영향을 주지 않는다.

## 최종 프로젝트

`index.html`, `style.css`, `server.json`의 제한된 형식을 해석한다. HTML은 제목 하나, CSS는 너비 하나, JSON은 장소 주소와 문의 보관을 다룬다. 일반 웹 서버나 임의 코드 실행기가 아니다. 미리보기와 검사기가 동일한 해석 결과를 사용하며 문의는 테스트 데이터로 명시한다.

검사·빌드·배포에는 같은 파일 해시가 연결되어야 한다. 배포한 파일은 보존하며, 마지막 편지는 동네 의뢰에서 고른 답장들이 결정한다. 세 결말은 주민 관계 중심, 도구와 작업 중심, 두 방향의 균형이다. 보상 금액은 답장에 따라 달라지지 않는다.

## 다음 사람 대상 확인

출시 판단에는 코드 경험이 없는 플레이어가 설명 없이 첫 성공을 경험하는지, 한 토큰 문제를 스스로 다시 풀 수 있는지, 도움을 접은 유사 문제에서 개념을 옮겨 쓰는지를 관찰해야 한다. 현재 자동 검사는 도움을 활용한 기능 검사이며 교육 효과를 측정하지 않는다. 카페·의뢰·엔딩의 실제 소요 시간 역시 별도로 측정한다.
