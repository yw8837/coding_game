# 0.14 정식판 RC — 실제 플레이 검증 보완

대상 빌드: `0.14.0-rc.0`, 게임 소스 `6c650bb`. 기존 [진행 안내](protocol.md)의 동의·익명 기록·저장 보호 원칙을 그대로 사용한다. 아래는 **앞으로 관찰할 항목**이며, 수행 결과나 재미 검증 성공이 아니다. 자동 검증 결과는 [QA 보고서](../QA-0.14-RC.md)에 따로 있다.

## 진행 순서

1. 같은 RC를 별도 테스트 계정에서 실행한다. 진행자의 기존 저장이나 참가자의 실제 저장을 초기화하지 않는다. 버전, 언어, 화면 크기, 입력 장치를 기록한다.
2. 초보자 첫 플레이와 코딩 경험자 첫 플레이를 분리한다. 기존 20~30분 프로토콜대로 정답·클릭 위치를 먼저 알려주지 않는다. 참가자가 요청한 도움과 게임 안에서 스스로 연 힌트를 각각 남긴다.
3. 후반 기능은 첫 플레이에서 실제 도달한 경우에 확인한다. 별도 진행 저장으로 시작했다면 **후반 기능 세션**이라고 표시하고, 첫 성공 시간·완주 시간·학습 효과 자료와 섞지 않는다. 테스트용 저장만 사용한다.
4. 오프라인 기록 도구의 관찰 근거와 전체 메모에 아래 항목을 기록한다. 기존 JSON/CSV 구조를 바꾸거나 미관찰을 성공으로 채우지 않는다.

## 초보자 — 어디를 고칠지 스스로 알 수 있는가

| 관찰할 상황 | 중립 질문 / 행동 근거 | 보완이 필요한 징후 |
| --- | --- | --- |
| 바탕화면에서 첫 의뢰로 이동 | 어디서 시작하는지 스스로 찾는지 기록 | 여러 창을 열고도 목적을 찾지 못함 |
| 코드를 고친 뒤 검사 실패 | “화면에서 무엇을 알 수 있나요?” | 실패 개수만 읽고 예상·실제 결과의 차이를 설명하지 못함 |
| 실패 결과에서 파일로 복귀 | 필요한 파일을 찾고 현재 입력을 이어가는지 | 파일 이동을 정답 적용이나 완료로 오해함 |
| 저장하지 않은 수정 / 검사 뒤 재수정 | 저장·검사 상태를 어떻게 이해하는지 | 이전 성공을 현재 코드의 성공으로 착각함 |
| 힌트 사용과 닫기 | 요청해서 열고 닫은 뒤 스스로 이어가는지 | 도움을 닫으면 현재 목표나 입력을 잃음 |
| 수정 후 손님에게 전달 | “이 작업으로 무엇이 달라졌나요?” | 체크 표시나 크레딧만 알고 손님의 문제를 설명하지 못함 |
| 다른 의뢰 선택 | 다음에 하고 싶은 일을 스스로 고르는지 | 가능한 다른 일이 있는데 같은 조작만 반복함 |

첫 60초 목적 발견, 첫 수정의 원인·결과 이해, 자발적인 다음 의뢰 선택은 관찰 목표다. 목표 시간에 도달했다고 성공 판정을 자동 부여하지 않는다. 도움을 썼다는 이유만으로 플레이 실패로 취급하지 않는다.

## 경험자 — 직접 작업과 다른 해법이 재미를 유지하는가

- 직접 작업 설정에서 타이핑, Tab, 명령 기록, `clear`, 파일 편집을 예상대로 사용하는지 본다. 지원하지 않는 명령은 명령·기대 동작·실제 오류를 기록한다.
- JavaScript를 지원하는 의뢰에서 예시와 다른 구현을 시도하면 해당 코드와 실제 검사 결과를 남긴다. 지원 문법과 조건을 벗어난 실패, 조건을 만족했는데 거부된 실패를 구분한다.
- 검사 결과의 예상값·실제값이 수정할 방향을 주는지 본다. 파서가 확인한 줄과 단순 관련 파일 안내를 혼동하는지도 기록한다.
- 반복 검사·완료 기록 방문이 보상을 다시 주거나 성공 연출만 남기는지 확인한다. 자동 QA에서 통과했더라도 사람이 혼동한 순간은 별도 UX 발견으로 기록한다.
- “반복으로 느껴진 구간은 어디였나요?”, “이어서 만들거나 고치고 싶은 것이 있나요?”라고 묻는다. 긍정적인 답이나 구매 의향을 유도하지 않는다.

## 엔딩 뒤 — 내 작품을 계속 다루는가

| 확인할 행동 | 관찰할 결과 |
| --- | --- |
| 엔딩 이후 미완료 의뢰로 복귀 | 남은 일을 찾고 기존 진행에서 이어갈 수 있는가 |
| 납품한 작품 기록 다시 열기 | 손님 반응·변경 결과·보상이 자신의 작업과 연결되는가 |
| 첫 출시 작품에서 독립 작업본 시작 | 최초 출시 기록과 현재 편집본의 차이를 이해하는가 |
| 지원 프로젝트의 내용·스타일 변경 후 검사 | 실제 미리보기 변화와 현재 검사 상태를 설명할 수 있는가 |
| 스냅샷 저장 후 복원 취소·확정 | 취소가 작업을 보존하고, 확정은 무엇을 되돌리는지 이해하는가 |
| HTML 내보내기 취소 / 저장 | 취소와 저장 성공을 구별하고 파일 위치를 찾는가 |
| 게임 밖 브라우저에서 HTML 열기 | 검색·분류·로컬 문의를 사용할 수 있는가 |

지원하는 프로젝트는 디렉터리·행사 게시판·포트폴리오다. 내보낸 HTML의 문의는 해당 브라우저에 저장되며 인터넷 서버나 공개 호스팅이 아니다. 이 범위를 설명해 주기 **전에** 참가자가 무엇으로 이해했는지 기록하고, 오해가 있으면 설명한다. 지원 범위를 넘어서는 임의 코드 편집기라고 소개하지 않는다.

## 몰입감·사운드·언어

작업 성공 직후 가장 먼저 본 것과 기억한 것을 묻는다. 효과음·알림이 결과를 이해하게 했는지, 입력이나 읽기를 방해했는지, 같은 연출이 반복돼 피곤했는지를 실제 행동과 함께 남긴다. “도파민이 늘었다” 같은 측정하지 않은 결론으로 바꾸지 않는다.

한국어·영어·일본어는 읽을 수 있는 참가자에게 각각 확인한다. 메뉴와 의뢰 표현, 오류 설명, 줄바꿈, 단축키, 고정 너비의 잘림을 구체적인 화면으로 기록한다. 번역 키 존재나 자동 테스트 통과를 원어민 검수로 간주하지 않는다.

## 출시 판단에 넘길 기록

- 멈춘 위치, 기대했던 동작, 실제 동작, 도움 출처, 재현 절차를 남긴다. 저장 손실·진행 불가·조건을 만족한 해법 거부는 우선 수정 대상이다.
- 평균 점수보다 같은 혼동이 서로 다른 사람에게 반복되는지 먼저 본다. 작은 표본을 전체 구매자나 중상급 코딩 학습 효과로 일반화하지 않는다.
- 두 번째 Windows PC의 설치 없이 실행·저장·재실행·HTML 내보내기 결과와 기기 조건을 별도로 기록한다.
- 자료가 아직 없으면 `미실시`로 남긴다. 올바른 Steam AppID/설정·Steam 검수, 언어 검수, 독립 플레이 검증은 여전히 출시 전 남은 조건이다.
