## SEC-01 — High: 빌드용 braces의 자원 고갈

- 공식 항목: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
- npm 최신 버전과 설치 기준은 `3.0.3`; 조사 시 공식 수정 버전은 없다.
- 영향: ESLint와 Vinext의 `fast-glob → micromatch → braces`가 비정상적으로 깊은 패턴을 처리하면 재귀 스택 고갈로 도구 프로세스가 실패한다. 게임의 가상 터미널/코드/저장을 이 빌드 패턴 처리기로 전달하는 연결은 확인하지 못했다. 원격 게임 사용자에 의한 호스트 코드 실행으로 확대 해석하지 않는다.
- 수정: `patches/braces@3.0.3.patch`를 `pnpm-workspace.yaml`의 `patchedDependencies`로 연결한다. 공유 store를 직접 편집하지 않으며, 패치 해시는 잠금 파일에 보존한다. 공식 원본의 버전 번호·라이선스·감사 결과를 바꾸거나 경고를 무시하는 설정은 추가하지 않는다.

패치는 parser의 괄호/중괄호 중첩과 직접 AST 입력의 깊이·노드·부모 순환을 검사한다. 깊이 100, 노드 20,000, 결과 10,000, 확장 작업 100,000, 누적 생성 문자 1,000,000을 상한으로 둔다. 호출자의 `rangeLimit:false`도 이 프로세스 자원 한도를 해제하지 않는다. 보통의 glob보다 훨씬 큰 입력은 안전하게 거절하는 의도적인 호환성 제한이다.

초기 패치의 범위 숫자 검사와 실제 `fill-range`의 숫자 변환이 달라 지수·16진수 등의 우회를 허용하는 문제가 독립 검토에서 발견됐다. 실제 `fill-range`와 같은 숫자 판별을 적용하고 안전 정수 범위를 벗어나는 끝점을 사전 거절하도록 수정했다. 이 실패를 발견하기 전 결과를 최종 통과로 사용하지 않는다.

추가 검토에서 각각 한도 안에 있는 stepped range를 반복하면 compile 결과의 누적 크기가 한도를 넘는 문제도 발견했다. compile의 전체 열거 작업과 생성 문자열, stringify의 escaping 후 결과까지 호출별 예산으로 계산하도록 보완했다.

직접 AST의 범위 토큰이나 실제 적용되는 step 옵션에 객체가 들어오면 하위 라이브러리가 이를 다른 옵션으로 재해석하는 우회도 발견했다. 범위 토큰·적용 step의 타입과 인수 수를 검사하고, 문자열로 합쳐지는 AST 숫자·불리언의 길이도 계산한다. 배열·객체 값은 거절한다. JavaScript getter 같은 임의 실행 객체를 안전하게 실행해 주는 샌드박스를 제공한다는 주장은 하지 않는다.

`scripts/test-braces-security.cjs`는 시간·메모리·스택을 제한한 별도 프로세스로 73개 비정상 입력을 검사한다. 소스 복사본의 기본/compile/expand/stringify/escaping 동작은 정상 패턴·옵션 조합 47개에서 원본과 결과 및 예외를 비교한다. 허용되는 경계 출력 10개도 길이와 전체 문자열 SHA256을 원본과 비교했다. 별도 검토자가 이 검사를 재실행했다. `scripts/verify-braces-install.mjs`는 두 실제 의존 경로를 해석해 설치된 패키지에 동일한 방어 검사가 통과하는지 확인한다. `pnpm verify`에도 설치본 검사를 넣었다.

**원본 registry 감사에는 High 1건이 계속 표시된다.** 등록된 `3.0.3`의 공식 수정 릴리스가 없기 때문이다. 이 항목의 상태는 “프로젝트에서 제한 패치 적용 및 확인, 업스트림 수정 대기”이며 “공식 취약점 0건”이라고 주장하지 않는다. 버전만 검사하는 감사 도구를 패스시키려고 버전을 위장하지 않는다. 공식 수정 릴리스가 나오면 정상 동작·경계 검사를 유지하며 로컬 패치를 제거할 수 있다.

증거: `output/0.13.1-qa/audit-before.json`, `braces/probes.json`, `braces/review-probes.json`, 최종 `output/quality-gate/braces-install.json`, 원본 audit JSON.

## 렌더러와 배포 경계

이미지 경고 수정은 `Image unoptimized`와 명시적 크기를 사용한다. Windows는 실제 Next의 브라우저 구현을 사용하고 네 가지 프레임워크 상수만 치환한다. `process` 전역 shim, Node 통합, 네트워크 허용을 추가하지 않는다. Vinext 이미지 shim이 가져오는 라이브러리의 설치된 라이선스 문서가 부족해 첫 빌드가 차단됐으며, 이를 우회하거나 추정한 라이선스를 추가하지 않았다.

브라우저 검사는 손상·과대 저장 거절과 기존 저장 보존, HTML 미리보기의 스크립트·외부 요청 차단, 제한 코드 실행기의 과도한 반복·전역 접근 거절과 정상 실행 복귀를 포함한다. Windows 검사는 Node 비노출·네트워크 차단·저장/복구를 확인한다. 패키지 검사에서는 QA 플래그 false, Steam ID null, 실행 fuse, 실제 QA판과 게임 파일 동일성 및 라이선스를 검사한다.

로컬 사용자 저장은 인증된 원격 안티치트가 아니다. 사람의 학습 효과와 재미, 실제 다른 PC 설치, 코드 서명과 Steam 심사는 이 자동 검증의 결과가 아니다.
