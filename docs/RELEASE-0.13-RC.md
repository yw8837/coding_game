# 0.13 RC — 의뢰 선택과 여러 풀이

카페 입문 3장 이후 각 구역의 6개 의뢰 중 4개를 골라 진행한다. 12개를 완료하면 최종 프로젝트를 시작할 수 있다. 남은 6개는 같은 보상을 받는 선택 의뢰로 남으며, 엔딩 이후에도 할 수 있다. 다음 의뢰 제안은 아직 진행 목표를 채우지 않은 구역을 우선한다.

## 같은 요청, 다른 코드

빵집 가격·도서관 대출·연락처 정리·배달비·축제 정산의 다섯 의뢰는 설정 파일을 고치거나 `function solve(input)`을 JavaScript로 직접 작성할 수 있다. 보상은 같고, 저장한 두 풀이를 오가도 코드가 유지된다. 코드 작성 중 다른 의뢰를 보러 가도 같은 앱 세션의 미저장 초안은 유지된다. 저장하지 않은 코드는 검사·전달에 쓰지 않는다.

판정은 예제 코드와의 문자열 일치가 아닌 여러 입력의 반환값을 사용한다. 반복문, 조건문, 배열 `map/filter/reduce` 등 구조가 다른 풀이를 확인했다. 직접 JSON 입력을 넣고 기대값과 실제 반환값을 비교할 수 있으며, 힌트는 사용자가 열 때만 나타난다. 임의 입력 실험은 보상을 지급하지 않는다.

가상 터미널에서도 같은 파일을 사용한다.

```sh
cd /home/dev/jobs/bakery-price
node solution.js '{"quantity":17}'
node --test solution.js
```

게임 안에 `nodejs`가 설치되어 있어야 한다. 실제 운영체제의 Node가 아닌 기존 제한 JavaScript 해석기에서 실행하며 전체 JavaScript·외부 패키지·네트워크를 지원하지 않는다. 유한한 자동 검사가 모든 가능한 입력의 정확성을 증명하는 것은 아니다.

공방 시간표도 고정 시각만 정답으로 요구하지 않는다. 09~13시 안에서 A→B→C 순서로 각 60분, 겹치지 않는 배치를 인정한다. 쉬는 시간을 두거나 시작을 늦출 수 있다.

## 내 첫 작품

마지막 작품의 목적을 장소 모음·행사 안내·포트폴리오 중에서 정하고, 소개·항목·분류를 직접 작성한다. 세 가지 색과 목록/카드 배치를 고를 수 있다. 실제 미리보기의 검색·분류·문의 대상이 저장한 내용과 연결된다. `project.json`을 직접 편집해도 같은 결과를 낸다. 수동 예시는 별도로 열어 보는 자료다.

화면 폭도 `100%`만 허용하지 않는다. 안전하게 지원하는 CSS에서 넘침과 읽을 수 있는 너비를 검사한다. `90%`, `max-width`를 둔 고정 너비, 적절한 `auto` 등 여러 구성이 가능하다. 사용자 HTML·임의 CSS·코드를 실제 DOM에 실행하는 웹 호스팅 서비스는 아니다.

## 저장과 마감

- 엔딩 당시 의뢰 목록을 보관해 추가 작업으로 결말이 바뀌지 않는다.
- 기존 3파일 출시 프로젝트와 해시는 유지한다. 새로 만드는 프로젝트는 형식을 따로 기록해 콘텐츠 파일을 지우고 검사를 건너뛸 수 없게 한다.
- 잘못된 JavaScript 모드 파일을 열어도 편집 화면을 복구할 수 있다. 지원하지 않는 의뢰에 우연히 `solution.js`가 생겨도 기존 편집 화면을 유지한다.
- 밝은 결과 카드의 글자 대비와 중복 React 키를 수정했다.

참고한 [코딩 학습 저장소 조사](coding-learning-references.md)에는 실제 소스와 라이선스 링크가 있다. 외부 엔진을 설치하거나 과제·이미지·예제 답안을 복사하지 않았다.
