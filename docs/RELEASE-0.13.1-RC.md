# 0.13.1 RC — 수리의 성취감과 실행 검증

0.13의 의뢰 선택·JavaScript 풀이·개인 프로젝트 기능은 유지하고, 정적 경고와 실제 상태 동기화·렌더링·빌드 문제를 수정한다.

## 내가 고친 결과를 보는 순간

수정한 파일을 검사해 통과하면 원래 고객 파일의 결과와 지금의 결과를 비교한다. 검사 성공은 작은 녹색 표시와 짧은 밝은 효과음, 납품은 실제 받은 크레딧·XP, 구역의 네 번째 납품과 첫 1.0.0 배포는 더 큰 목표 달성 연출로 구분한다. 파일을 저장하지 않았거나 검사 기록이 오래됐을 때는 성공 화면을 보여 주지 않는다.

납품 뒤에는 고객 답장과 구역 진행, 다음 목표, 번 크레딧을 쓸 작업실로 이어진다. 입력을 잠그는 컷신이나 자동으로 펼쳐지는 힌트는 없다. 이미 통과한 같은 검사를 다시 누르거나 저장을 불러오는 행위로 큰 성공 연출이나 보상이 반복되지 않도록 했다. 동작 줄이기 환경에서는 해당 움직임을 생략한다.

이는 기존 결과와 보상을 읽기 쉽게 만드는 마감이며 보상 금액·정답 판정·진행 조건을 완화하지 않는다. 실제 사람의 재미가 향상됐다는 결론은 별도의 플레이 관찰로 확인한다.

## 상태·빌드·보안 마감

- 미사용 코드, 불명확한 React effect 의존성, 이미지 크기·로딩 처리를 정리했다. 기존 검사 규칙을 낮추지 않고 `lint --max-warnings 0`을 적용했다.
- Ghrom 이전/다음 탐색 기록은 인덱스와 함께 갱신한다. 의뢰 집중 요청은 토큰당 한 번 처리하고, 일반 상태 변화가 사용자의 수동 의뢰/파일 선택이나 터미널 입력을 덮어쓰지 않도록 했다.
- 밝은 프로젝트 미리보기의 목록 불러오기 버튼은 기본/hover/focus 글자 대비를 유지한다.
- 클라이언트 코드 청크를 분리하면서 React 초기화 순서를 명시적으로 유지한다. 실제 production 서버에서 시작 버튼 활성화와 이미지 로딩을 검사한다.
- Windows 이미지 처리는 최적화 서버를 요구하지 않는다. CSS의 로컬 이미지 경로를 빌드에서 해석하되 게임 그림만 복사하여 웹 홍보 영상은 포함하지 않는다.
- 빌드 의존성 `braces`에는 자원 제한 패치를 적용하고 실제 설치 경로도 검사한다. 공식 수정 릴리스는 없어 원본 감사에 High 1건이 계속 보이는 점을 [보안 기록](security/review-0.13.1.md)에 명시한다.
- `pnpm verify`는 lint, 타입, 실제 설치된 방어 패치, 게임/데스크톱 단위 검사를 순서대로 실행하고 실패 시 중단한다. 브라우저/실행 파일 검사는 별도이며 이를 단위 검사 통과로 대신하지 않는다.

저장 형식과 기존 진행 기록은 유지한다. [최종 QA 기록](QA-0.13.1-RC.md)에 실제 실행 결과와 미검증 범위를 기재한다. 이 버전도 Steam 정식 출시가 아닌 Windows 오프라인 RC다.
