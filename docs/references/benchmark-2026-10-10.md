# HackHub 추가 자료 비교 · 2026-10-10

사용자 요청은 화면·캐릭터·미션을 복제하는 것이 아니라, 처음 조작부터 의뢰와 성취까지의 흐름을 비교해 CODE:SHIFT의 완성도를 높이는 것이다. 현재의 동네·작업실·캐릭터 그림, 밝은 분위기와 “내 첫 출시” 목표를 유지한다.

## 실제 확인한 자료와 한계

무료 로컬 `yt-dlp`로 공개 영상 메타데이터와 재생목록을 읽었다. 두 번째 영상의 자막 요청은 HTTP 429로 실패했으나 `youtube-transcript-api`에서 영어 자동 자막 1,963개 구간을 확보했다. 자동 자막의 단어 오류는 원문 그대로 사실로 채택하지 않았다. 전체 영상을 연속 시청한 것은 아니다.

스토리보드는 320×180 프레임의 묶음이다. 창 배치와 전환은 볼 수 있지만 작은 글자의 정확한 내용, 입력 지연, 사운드와 전체 플레이 속도는 검증할 수 없다. 두 번째 영상의 자동 챕터에는 역순 시각 경고가 있으므로 챕터 제목이나 긴 마지막 구간을 근거로 “플레이어가 오래 막혔다”고 단정하지 않는다. 재생목록의 영상 길이도 실제 초보자의 플레이타임이 아니다.

## 채택한 원칙과 현재 구현

| 관찰 / 설계 판단 | 우리 게임의 적용 | 검증 위치 |
| --- | --- | --- |
| PC 앱을 직접 열고 창을 넘나드는 행위가 시뮬레이터의 감각을 만든다. | 빈 바탕화면에서 시작. 하단 작업표시줄, 시계·달력, 시작 메뉴·최근 파일, 이동·크기 조절·최소화·닫기 지원. 현재 그림과 색을 유지한다. | `DesktopOS.tsx`, native / packaged E2E |
| 여러 앱이 겹쳐도 다음 목표를 잃지 않아야 한다. | 창 밖 현재 목표, 필요한 앱 열기, 사용자의 수동 창·파일 선택 유지. 0.13.1에서 탐색 기록과 집중 요청의 반복 처리를 보완했다. | `workflow.ts`, `Browser.tsx`, `CareerView.tsx`, state-sync E2E |
| 도구 준비만 길어지면 첫 성취가 늦어진다. | 함께 배우기는 복사·준비·미리보기의 세 단계. 숙련자는 같은 상태를 명령으로 조작. 실제 준비 완료 전 다음 단계로 넘어가지 않는다. | `setup.ts`, coach / native E2E |

| 짧은 성취와 장기 목표의 크기를 달리한다. | 입문 3장, 구역마다 6개 중 4개 선택, 12개 뒤 개인 프로젝트. 남은 6개는 같은 보상으로 계속 가능. 크레딧은 배경·작업실 도구에 사용한다. 0.13.1에서는 검사/납품/구역 개방·출시의 성공 연출 크기를 구분하고 납품 결과에서 도구 상점으로 연결한다. | freedom / learning E2E, 게임 단위 검사 |

현재 구현과 이번 새 자료의 관찰을 대조한 기록이다. 기존 기능을 새 영상 덕분에 새로 만든 것처럼 표시하지 않는다. 새 영상의 코드·미션 대사·배경·아이콘·캐릭터는 가져오지 않았으며 레퍼런스 프레임은 제품/홍보물에 넣지 않는다.

## 출시 전 사람에게 확인할 항목

[플레이 검증 안내](../playtest/protocol.md)에 첫 목표 발견, 수정과 결과의 인과 이해, 선택 의뢰 발견, 숙련자의 자유 풀이를 추가했다. 자동 완주와 별도로 초보자 3~5명·경험자 2~3명에게 확인한다. 모집·연락·참가자 결과는 아직 없다. 새로운 기능을 더 많이 넣기보다 실제로 멈춘 구간과 반복적인 조작을 이 관찰로 찾아 수정한다.

홍보 영상 재촬영 시에도 터미널만 이어 붙이지 않는다. “고장 난 주문 → 플레이어의 한 수정 → 올바른 계산과 손님 반응 → 보상/꾸미기 → 내 첫 작품”을 연결하고 실제 조작 화면을 사용한다. 기존 0.11.1 영상은 유지하며 최신 기능 촬영본으로 표시하지 않는다.
