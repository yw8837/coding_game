# HackHub 한국어 영상·19개 재생목록의 실제 화면 확인 · 2026-10-10

## 확인 방식과 한계

기존 320×180 스토리보드 확인을 보완하기 위해 공개 YouTube 영상을 무료 로컬 yt-dlp로 720p 영상 트랙으로 확보하고, ffmpeg로 실제 프레임을 추출했다. 브라우저 쿠키·유료 전사·외부 키를 사용하지 않았다. 연구 파일은 임시 폴더에 있으며 제품에는 넣지 않는다.

전체 시간을 연속 재생하여 시청한 것은 아니다. 아래 시각의 실제 영상 프레임을 처음부터 끝부분까지 순서대로 읽은 **화면 표본 분석**이다. 짧은 영상은 10초 간격, 200초 초과 미션은 45초 간격, 한국어 긴 영상은 90초 간격이며 마지막에서 3초 앞의 프레임도 포함했다. 프레임 사이의 순간 입력, 소리, 애니메이션 속도, 플레이어의 생각은 검증하지 못했다. 완료 장면이 없는 영상에서 완료를 추정하지 않는다.

공통 임시 경로: `C:/Users/최용우/AppData/Local/Temp/codeshift-reference-20261010`. 원본은 `{id}.mp4`, 표본은 `actual-{id}/frame-{초:04d}.jpg`, 읽은 연락판은 `actual-{id}/sheet-00.jpg`부터 마지막 번호까지다. 960px 너비 프레임 두 열, 최대 여섯 프레임을 한 장에 배치했다. 정확한 전 표본 시각은 `actual-visual-manifest.json`에 있다.

한국어 gMjduQanVn4에 yt-dlp `--write-sub --write-auto-sub --sub-langs ko,en --skip-download`를 실행했으나 요청 언어 자막이 없었다. youtube-transcript-api도 `TranscriptsDisabled`를 반환했다. 이 기록은 발화 전사를 근거로 사용하지 않는다. 재생목록 총 길이는 메타데이터 기준 **6,729초(1:52:09)**이며, 영상 길이를 초보자 플레이타임으로 해석하지 않는다.

재생목록 19개 모두 공개 영상 트랙을 확보했다. Cryptographer Hunt는 최초 직접 형식 298에서 HTTP 403이 발생했으나 `136/bestvideo[height<=720][protocol=m3u8_native]/bestvideo[height<=480]` 재시도에서 공개 HLS 형식 612로 성공했다. 19개 재생목록 252프레임, 한국어 긴 영상 46프레임, 총 **298프레임**을 시간순으로 읽었다. 별도로 Is Host Working 00:46.5의 `end-extra.jpg` 한 프레임도 읽었으며 같은 완료 준비 상태를 확인했다. 나머지 짧은 세 미션의 메타데이터 종료 0.5초 전 추가 추출은 이미지가 생성되지 않았으므로 확인 범위에 포함하지 않는다.

## 구현에 넘길 구체적인 원칙

1. **검사 성공 후 목적 전환:** 검사 통과 시 현재 목표를 '손님에게 납품하고 결과 확인'으로 바꾸고 다음 행동을 찾을 수 있게 한다. 결과 자동 납품은 하지 않는다.
2. **짧은 현재 목표와 접힌 이력:** 긴 의뢰에서도 현재 한 단계, 필요한 파일·앱, 성공 조건을 읽을 수 있어야 한다. 지난 체크 목록은 펼쳐 볼 수 있게 보관한다.
3. **자료와 수정 화면의 왕복:** 손님의 문제 화면, 코드·파일, 수정 후 결과를 가까이 두고 기존 창·파일 상태로 복귀한다. 앱을 강제로 순서대로 닫아 진행시키지 않는다.
4. **변화의 인과를 실제 화면으로:** 주문 합계·시간표·출시 페이지 등 결과가 코드 변경으로 달라지고, 실제 납품 이후 같은 고객이 반응한다. 성공 문구만으로 결과를 대신하지 않는다.
5. **사용자가 여는 단계 도움:** 설명·예시를 작업 맥락에서 읽고 닫으면 현재 파일과 입력을 계속 사용할 수 있어야 한다. 해설을 늘리는 것만으로 학습을 대체하지 않는다.

새 구현의 완료 여부는 별도 코드·실행 증거로 검증한다. 이 문서는 레퍼런스 관찰과 그 관찰에서 얻은 설계 판단만 기록한다.
