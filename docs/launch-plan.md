**2026-10-09 방향 갱신:** 최종 제품은 Steam PC판, 한국 기준가 21,000원이다. 현행 공개 버전과 아래 브라우저 홍보안은 검증용 빌드의 기록이다. 제목은 미정이며, 새 정식판 방향·자동 언어 정책·가격 범위는 [STEAM-RELEASE-PLAN.md](STEAM-RELEASE-PLAN.md)를 따른다. 아래 40초 편집안은 기획 기록이고 실제 납품 영상은 42초다.

## 제품과 대상

현재 소스의 게임은 모노 카페의 온라인 오픈을 돕는 세 의뢰의 브라우저 캠페인이다. Windows를 연상시키는 가상 바탕화면에서 메시지, 브라우저, 에디터, 터미널, 서버, API 앱을 직접 조작한다. 첫 의뢰는 HTML 간판과 CSS 너비, 두 번째는 계산 연산, 세 번째는 메뉴 주소와 주문 보관 설정을 고친다. 명령과 서버는 게임 안의 가상 환경이다.[1][2][3]

대상은 코딩 경험이 없는 15세 전후 플레이어다. 이는 디자인 목표이며 공식 이용 등급이나 실제 청소년 대상 사용성 검증을 뜻하지 않는다. 한국어·영어·일본어 인터페이스를 제공하지만 코드·명령은 번역하지 않는다. 저장은 현재 브라우저에 남는다. 일반 개발 환경, 운영체제, 범용 Python 실행기라는 설명은 쓰지 않는다.[1][2]

플레이어가 기대할 구체적 행동은 **“고장 난 화면을 보고 → 작은 값을 고치고 → 결과를 확인하고 → 카페에 전달하기”**다. 홍보의 중심 증거는 터미널 입력, 실제 에디터 수정, 바뀐 미리보기다. 장르 표현은 “브라우저 코딩 퍼즐 게임”으로 통일한다. 학습 효과, 완주 시간, 사용자 수, 만족도, 무료·무설치·계정 불필요·모바일 완벽 지원은 해당 공개 버전에서 확인한 항목만 추가한다.

## 40초 실제 플레이 홍보 영상

영상에 동작을 대신하는 장식 모션이나 긴 로고 인트로를 넣지 않는다. 짧은 클릭·검사 효과음이 있다면 실제 게임에서 녹음하거나 출처와 사용 권한이 확인된 로컬 자산을 쓴다. 음악이 없더라도 플레이 캡처와 캡션으로 완성한다. Playwright 녹화는 화면 중심이므로 게임 음성이 함께 기록된다고 가정하지 않는다. 생성 영상으로 실제 플레이를 대신하지 않는다.[5]

**읽기와 현지화:** 한 장면에 한 언어·한 줄, 최대 두 줄. 코드 편집 영역과 퀘스트를 캡션으로 가리지 않는다. KO/EN/JA는 같은 타임라인에 각각 교체하고, 세 언어를 동시에 겹치지 않는다. 자막 파일을 함께 제공하고, 한국어·일본어 문장은 해당 언어로 검수한다. 브랜드 제목은 확정 전까지 작업명임을 표시한다.

**세로 버전:** 1080×1920, 9:16. 전체 데스크톱을 자동 중앙 크롭하면 편집기·퀘스트·작업 표시줄이 사라질 수 있다. 첫 버전은 1920×1080 플레이 화면 전체를 세로 캔버스 중앙에 배치하고 위·아래에 짧은 캡션을 둔다. 이후 각 샷의 실제 편집 영역을 지정한 수동 리프레임을 검토한다. 데스크톱 버전보다 모바일에서 글자가 작아지므로 폰 크기로 미리 보고 코드 값이 읽히는지 확인한다.

### 캡처 코드의 핵심 계약

다음은 제작 스크립트에 넣을 최소 형태다. 공개 URL과 실제 UI 조작 함수는 제작자가 채운다. `page.evaluate`나 저장값 삽입으로 해결 결과를 만드는 대신 실제 플레이를 수행한다. 원본 영상이 파일로 완성되려면 `context.close()`를 기다려야 한다.[8]

```js
// Node ESM. 추가 패키지 설치 없이 번들 패키지를 사용한다.
import { createRequire } from 'node:module';
const require = createRequire(import.meta.url);
const { chromium } = require(
  'C:/Users/최용우/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright'
);
const browser = await chromium.launch({ headless: true });
const context = await browser.newContext({
  viewport: { width: 1920, height: 1080 },
  recordVideo: { dir: 'promo/source', size: { width: 1920, height: 1080 } },
});
const page = await context.newPage();
await page.goto(process.env.PROMO_GAME_URL, { waitUntil: 'networkidle' });
// await captureActualUiPlaythrough(page); // 실제 UI 조작; 씬별 시간 기록
await context.close();
await browser.close();
```

수동 촬영이 필요하면 이미 설치된 FFmpeg의 `gdigrab`도 가능하다. 개인정보가 없는 게임 전용 창을 앞에 놓고 창 제목이 일치하는지 확인한 뒤 아래를 실행한다. `title=…`는 실제 창 제목으로 교체한다. 녹화 종료는 `q`다. Windows 제목·배율에 따라 실패할 수 있으므로 자동 제작의 기본은 Playwright로 둔다.[9]

```powershell
ffmpeg -hide_banner -f gdigrab -framerate 30 -draw_mouse 1 -i 'title=실제 게임 창 제목' -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p 'promo/source/raw.mp4'
```

### 편집·검증 명령

다음 명령은 제작 단계용이며 이 문서 작성 중 실행한 렌더가 아니다. 실제 raw 촬영 시간을 보고 EDL의 `sourceIn`을 기록한다. 제시된 12초 시작점은 형식 예시이며 실제 녹화의 사건 시각을 뜻하지 않는다. 프레임이 아닌 키프레임으로 잘리는 stream-copy 대신 재인코딩해 컷 정확도를 확보한다.

`promo/work/concat.txt`는 UTF-8로 아래 순서대로 저장한다. 각 파일의 목표 길이는 위 샷 표의 3/3/4/5/5/5/5/5/5초다. 입력 녹화가 여러 개라면 EDL은 각 샷의 `source`도 기록한다.

```text
file '01.mp4'
file '02.mp4'
file '03.mp4'
file '04.mp4'
file '05.mp4'
file '06.mp4'
file '07.mp4'
file '08.mp4'
file '09.mp4'
```

```powershell
# 실제 EDL에 따라 각 샷을 만든다. 예: 원본 12초에서 시작하는 3초 컷.
ffmpeg -hide_banner -i 'promo/source/raw.webm' -ss 12 -t 3 -an -vf 'fps=30,scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1' -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p 'promo/work/01.mp4'

# concat.txt의 모든 샷은 동일한 해상도·프레임레이트·영상 코덱으로 정규화한다.
ffmpeg -hide_banner -f concat -safe 0 -i 'promo/work/concat.txt' -c copy -movflags +faststart 'promo/output/promo-master.mp4'

# KO 자막을 별도 트랙으로 포함한다. EN/JA도 같은 방식.
ffmpeg -hide_banner -i 'promo/output/promo-master.mp4' -i 'promo/source/captions.ko.srt' -map 0:v:0 -map 1:0 -c:v copy -c:s mov_text -metadata:s:s:0 language=kor -movflags +faststart 'promo/output/promo-ko.mp4'

# 전체 플레이 화면을 보존하는 세로 변환. 별도 자막·캡션은 위아래 여백에 배치한다.
ffmpeg -hide_banner -i 'promo/output/promo-master.mp4' -vf 'scale=1080:-2,pad=1080:1920:(ow-iw)/2:(oh-ih)/2,setsar=1' -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -an -movflags +faststart 'promo/output/promo-vertical.mp4'

# 미디어 규격과 실제 길이 확인; 30–45초인지 결과로 판정.
ffprobe -v error -show_entries 'format=duration,size:stream=codec_name,width,height,r_frame_rate' -of json 'promo/output/promo-master.mp4'

# 전체 파일 디코드 확인; 오류가 없는지 확인.
ffmpeg -v error -i 'promo/output/promo-master.mp4' -f null -
```

자막을 영상에 태우려면 FFmpeg `subtitles` 필터와 로컬 폰트를 사용하고, KO/JA 글리프를 실제 샘플 프레임에서 확인한다. MP4의 선택 자막만으로 모든 플랫폼에서 캡션이 보인다고 가정하지 않는다. SNS 업로드용은 자막을 영상에 태운 파일, 접근성과 수정용은 UTF-8 SRT를 각각 보존한다.

**편집 가능한 납품 묶음:** `promo/source/raw*.webm` 또는 MP4, `promo/source/edl.json`(샷 id·sourceIn·duration·crop·caption key), `captions.ko/en/ja.srt`, `promo/render.mjs` 또는 PowerShell 편집 스크립트, 권리가 확인된 음원 및 출처 파일, `promo/output/*.mp4`, `promo/README.md`(재실행 명령·원본 촬영 버전·검증 결과). 파일명은 제작 시 확정한다. 최종 영상만 전달해 재편집 가능성을 잃지 않는다.

**납품 판정:** 길이 30–45초, 1920×1080 마스터와 필요 시 1080×1920 세로본, 전체 디코드 성공, 장면별 실제 UI 조작 증거, 오탈자·KO/JA 글리프 확인, 첫 프레임·마지막 프레임·각 컷 경계의 검은 화면/잘못된 이전 상태 확인. 동영상이 생성·검증되기 전에는 “홍보 영상 완료”라고 보고하지 않는다.

## 랜딩 페이지: 게임 밖에 두는 SEO·AEO·GEO 콘텐츠

읽을 수 있는 소개를 `/about`, `/about/en`, `/about/ja`에 서버 렌더된 정적 콘텐츠로 구현했다. 플레이 링크는 기존 `/`로 연결한다. 자기 canonical과 상호 hreflang, 페이지별 메타데이터, 언어가 지정된 콘텐츠, 검증된 속성만의 VideoGame 데이터와 일반 HTML FAQ를 제공한다. robots와 sitemap의 공개 출처는 `https://codeshift-lab.bsfire1237.chatgpt.site`다. 배포·색인 상태는 아직 이 작업에서 확인하지 않았다. 게임 안 언어 토글과 검색용 언어 URL은 서로 구분한다.[10]

검증된 플레이 영상·스크린샷에 설명과 alt를 붙이고 제작자, 버전, 실제 수정일, 문의·문제 보고 경로를 표시한다. 플레이 시간과 재미에 관한 사용자 인용은 동의를 받고 원문·조건을 보존한다. 근거 없는 교육 통계나 사용자 수는 넣지 않는다.

### 검색·인용 준비의 우선순위

| 순서 | 관찰과 작업 | 의존성 | 실패 판정 / 볼 지표 |
| --- | --- | --- | --- |
| 1 | 게임 canvas·client 화면만으로 제품을 설명하기 어렵다 → 세 언어의 읽을 수 있는 소개 HTML과 실제 캡처를 제공 | 공개 버전·명칭 확정 | JS 없이 가져온 HTML에 제품 설명·플레이 링크가 없음 / URL별 색인 확인 |
| 2 | 언어 토글과 검색 URL은 다르다 → 언어별 `lang`, 자기 canonical, 상호 `hreflang` (`ko`,`en`,`ja`,`x-default`)와 사이트맵 | 랜딩 URL 고정 | 잘못된 canonical·끊긴 alternate / Search Console 색인·언어별 유입 |
| 3 | 검색 방문자는 제품과 실행 범위를 궁금해함 → 위 답변·지원 환경·저장 방식·가상 실행 범위를 명확히 표시 | 최신 소스 사실 확인 | 방문자가 실제 OS를 조작한다고 오해 / 관찰 질문·버튼 클릭→게임 진입 |
| 4 | AI 검색도 읽을 수 있는 근거가 필요함 → 제작자·버전·직접 촬영한 영상·검증 범위를 링크 | 촬영·검증 기록 | 잘못된 버전/효과를 인용 / 날짜·질문·인용 URL을 수동 기록 |
| 5 | 검색 크롤러와 학습 크롤러는 역할이 다름 → 공개 도메인의 robots·HTTP·색인 상태를 각각 확인 | 공개 도메인·소유자 정책 | 아래 검색 봇별 차단 또는 오류 / 서버 접근 로그·색인 보고 |

`Googlebot`은 Google 검색, `OAI-SearchBot`은 ChatGPT Search, `Claude-SearchBot`은 Claude 검색, `PerplexityBot`은 Perplexity 검색에 대한 점검 항목이다. `GPTBot`, `ClaudeBot`, `Google-Extended` 같은 학습·별도 이용 제어는 검색 접근과 구분한다. 공개 URL을 아직 점검하지 않았으므로 “모두 허용”, “색인 완료”, “AI에 인용됨”, SEO/GEO 점수는 부여하지 않는다.[11]

구조화 데이터는 실제 내용을 설명하는 `VideoGame`과 촬영 영상의 `VideoObject`부터 검토한다. 확정 이름·URL·실제 썸네일·길이·게시일·지원 UI 언어만 넣는다. 존재하지 않는 `aggregateRating`, 공식 `contentRating`, 교육 성과, 가격, 플랫폼 출시, `sameAs` 계정은 넣지 않는다. FAQ는 사람이 읽는 일반 HTML 질문·답으로 충분하다. FAQ/HowTo 스키마가 검색 노출이나 AI 인용을 보장한다고 말하지 않는다. `llms.txt`는 우선순위가 낮으며 Google 순위·인용을 위한 필수 파일로 권하지 않는다. 키워드 반복·가짜 언급·무더기 블로그·위키 등재를 성장 방법으로 삼지 않는다.[11][12]

검색어 후보는 **조사 가설**이다. KO `코딩 퍼즐 게임`, `브라우저 코딩 게임`, `코딩 처음 게임`; EN `browser coding puzzle game`, `coding game for beginners`; JA `ブラウザ コーディング ゲーム`, `プログラミング パズル 初心者`. 검색량·순위·경쟁도는 측정하지 않았다. 첫 주는 실제 Search Console 질문과 사용자의 표현을 보고 범위를 좁힌다. 가상 게임이라는 사실을 전달하는 문구를 유지한다.

## 배포 채널과 게시 초안

처음에는 실제 플레이 영상 한 편과 소개 페이지 한 곳을 중심으로 시작한다. B2B SaaS용 LinkedIn 광고·MQL·SQL·큰 예산 기준을 이 청소년 지향 브라우저 게임에 그대로 적용하지 않는다. 캠페인 계획의 **목표→채널→추적→작은 시험→확대** 순서만 채택한다.[13]

| 채널 후보 | 게시물 | 목적 | 검토 조건 |
| --- | --- | --- | --- |
| YouTube | 40초 16:9 실제 플레이 영상 + 설명·자막·플레이 링크 | 조작과 결과를 명확히 보여줌 | 공개 버전과 영상 일치 |
| Shorts / Reels | 9:16 실제 플레이 편집, 같은 CTA | 처음 보는 사람에게 게임 유형 전달 | 작은 화면에서도 코드 값·행동이 읽힘 |

| 개발·퍼즐 게임 커뮤니티 | 제작자가 쓴 짧은 소개와 실제 화면, 피드백 요청 | 실제 초보자가 막힌 위치 수집 | 해당 커뮤니티 게시 규칙·홍보 허용 범위 확인 |

다음은 아직 게시하지 않은 초안이다. `[공개 URL]`은 실제 링크로 바꾸고, 각 채널 규칙에 맞게 편집한다.

**KO:** “메뉴판은 휴대폰 밖으로 삐져나오고, 커피 세 잔의 계산도 이상합니다. 가상 바탕화면에서 브라우저·터미널·에디터를 직접 열어 모노 카페의 세 의뢰를 고치는 게임을 만들고 있습니다. 영상은 실제 플레이를 40초로 편집했습니다. 한국어·영어·일본어 UI. 플레이: [공개 URL]”

**EN:** “The café menu spills off the phone screen, and three coffees have the wrong total. Open a browser, terminal, and editor on a virtual desktop to fix Mono Café’s three requests. This is an edited 40-second recording of actual gameplay. Korean, English, and Japanese UI. Play: [public URL]”

## 작은 시험부터 공개까지

1. **촬영 전:** 이름과 공개 경로를 임시 표시하고, 촬영용 새 게임을 플레이어 저장과 분리한다. 대상 버전·실제 UI 경로·촬영 시작 상태를 기록한다.
2. **제작:** 세 의뢰를 실제로 조작해 녹화한다. 40초 EDL과 KO/EN/JA 자막을 만들고 편집 가능한 원본을 남긴다.
3. **품질 확인:** 길이·전체 디코드·컷 경계·자막·게임의 사실을 확인한다. 공개 버전에서 영상에 보인 결과를 재현할 수 있는지 확인한다.
4. **초보자 관찰:** 코드 경험이 없는 참여자가 별도 설명 없이 첫 의뢰를 진행하는 모습을 본다. 연령에 맞는 참여 동의를 갖추고, 헷갈린 단어·다음 조작·중단 위치를 기록한다. 소수의 관찰로 통계적 교육 효과나 전원 완주를 주장하지 않는다.
5. **공개:** 외부 게시를 실행할 때는 소유자가 최종 내용을 확인한다. 게임·소개 페이지·영상·설명란의 이름·URL·지원 범위를 일치시킨다.
6. **공개 후 7일:** 영상→소개 페이지→게임 시작→첫 의뢰 수락→첫 검사→첫 보상의 전환을 비교하고 가장 많이 끊기는 단계 한 곳을 고친다. 영상 A/B는 첫 장면의 “잘린 메뉴판”과 “이상한 합계”만 바꾼다.

작업 순서는 의존 관계를 따른다. 현 시점에 참여자 수·기준값·공개 유입을 측정하지 않았다.

**측정안:** `utm_source=youtube|itch|community`, `utm_medium=video|referral`, `utm_campaign=launch-v1`, `utm_content=menu-ko|checkout-en`처럼 낮은 수의 일관된 UTM을 쓴다. 주 지표는 방문 수보다 **게임 진입 후 첫 의뢰 보상에 도달한 비율**로 두고, 영상 클릭률·첫 실행·첫 의뢰 수락·검사 오류·중단 위치를 앞단 지표로 본다. 실제 수집 전에는 이벤트를 도입하고 작동·중복 여부를 검증해야 한다. 코드 입력 내용·메시지 전문 같은 불필요한 데이터는 수집하지 않는다. 현재 소스에 프로덕션 분석이 설치됐다고 가정하지 않는다.
