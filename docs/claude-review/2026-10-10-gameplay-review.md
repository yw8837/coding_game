### 발견 사항

- **1-1 [확인] 슬라이더를 정확히 100%에 맞춰야 한다.** 판정은 `width: 100%` 정규식이다(`lesson.ts:26`). 안내 문구는 "두 메뉴가 화면을 채우게 맞춰 주세요"뿐이다(`CafeCoach.tsx:47`). 실패 문구도 "두 메뉴가 화면을 채우도록 맞춰 보세요"를 반복하며 현재 값이 얼마인지, 무엇이 기준인지 말해 주지 않는다(`CafeCoach.tsx:42`). [추정] 95%에서 휴대폰 화면은 이미 들어맞아 보인다. 그래서 "왜 안 되지?"가 첫 10분 안의 유일한 실패 지점이 될 가능성이 높다. "100%는 화면 전체 너비" 안내는 도움말을 열어야 보인다(`CafeCoach.tsx:48`). → CR-08
- **1-2 [확인] 가장 흔할 오답에 전용 안내가 없다.** 2장 연산자 칸은 `* + - /`만 받는다(`coach-edit.ts:21`). 3장 주소는 `/`로 시작해야 한다(`coach-edit.ts:25`). 그 밖의 입력에는 모두 "이 값은 아직 파일에 쓸 수 없어요. 도움말을 확인하거나 전체 코드에서 고쳐 보세요."가 뜬다(`CafeCoach.tsx:36`). [추정] 수학 시간에 `×`를 배운 학생은 `×`나 `x`를 먼저 칠 것이다. 그때 바로 "코드에서는 곱하기를 `*`로 써요"가 나와야 스스로 고칠 수 있다. 자동 변환은 하지 말고 안내만 한다. → CR-09
- **1-3 [확인] 목업과 실제 파일의 메뉴 수가 다르다.** 코치 휴대폰에는 음료가 2개다(`CafeCoach.tsx:54`, 안내 문구도 "두 메뉴"). 실제 `index.html`에는 3개가 있고(`content.ts:7`), 검사 항목은 "PC에서도 메뉴 3개 표시"다(`content.ts:16`). [추정] "전체 코드 보기"를 연 플레이어는 목업과 실제가 다르다고 느낀다. → CR-20

### 고리가 약한 의뢰

- **11 박물관 [확인]** CSS 레이아웃 의뢰인데 고객 화면에는 `320`, `768`, `900` 숫자만 나온다(`career-evaluation.ts:175`). 카페 1장처럼 실제로 넘치던 전시가 화면 안에 들어오는 장면이 없다. 이미 있는 미리보기 기반(`lib/game/preview.ts`)을 살리지 못한 가장 큰 기회다.
- **6 진료소 [확인]** HTML 폼 의뢰인데 결과는 true/false 세 줄이다(`career-evaluation.ts:130-132`). 라벨을 누르면 입력칸에 초점이 가는 장면, 빈 이름 제출이 막히는 장면이 없다.
- **8 방과후 [확인]** 단어 하나(`asc`→`desc`)로 끝나고, 결과는 이름 순서뿐이다. [추정] 18개 중 손맛이 가장 적다.
- **16 기록보관소 [확인]** 값 하나를 켜면 끝난다. 결과는 true/false와 39다. 2번과 같은 꼴이라 새로움도 낮다.
- **17 시간대 [확인]** 결과를 `D+1 08:00` 같은 프로그래머식 표기로 보여 준다(`career-evaluation.ts:219-220`). 표시 변환은 true/false/숫자만 다룬다(`CareerPlayground.tsx:18`). 의뢰문은 "다음날08"이라고 쓰는데 화면은 `D+1`이라 [추정] 입문자는 낯설어한다.
- **15 마을버스 [확인]** "원본 로그 모두 유지" 검사의 기대값·실제값이 정렬된 JSON 배열 문자열 통째로 검사 표에 들어간다(`career-evaluation.ts:208`).

## 4. 엔딩과 자유 제작

- **4-1 [확인] 최종 프로젝트의 필수 수정은 카페 수정의 재방송이다.** 시작 파일이 `<h1>Untitled</h1>`, `.portal { width: 960px; }`, `"route": "/places"`, `"saveRequests": false`이고(`release.ts:8-12`), 네 검사도 이걸 확인한다(`release.ts:47-55`). 새로운 건 `project.json`의 소개·항목·분류·색·배치 작성(`release-product.ts:2`)과 실제 미리보기다. 이 부분이 피날레의 중심이 되어야 한다. [추정] 카페 1·3장과 같은 수정이라 3구역보다 쉽게 느껴진다. "마지막 시험"이라기보다 "복습"이다.
- **4-2 [확인] 플레이어의 12개 선택이 작품에 들어가지 않는다.** 정렬·필터·일정·집계를 배운 의뢰를 했든 안 했든 최종 프로젝트는 똑같다. 지원 기능도 검색·분류·문의로 고정이다(`ReleaseProject.tsx:68`). → CR-10
- **4-3 [확인] 편지가 내 작품을 모른다.** 결말 3종의 본문은 고정문이다. `community`·`balanced`는 플레이어 작품을 "도움판"이라고 부른다(`CareerConclusion.tsx:21,23`). 0.10 설계의 "동네 도움판"(`docs/ENDING-AND-LEARNING.md:14`)이 남은 것이다. 지금은 작품 종류가 장소 목록·행사 안내·포트폴리오 셋인데(`release-product.ts:2`) 포트폴리오를 만들어도 "도움판"이라고 한다. 편지 바깥에 표시되는 개인 정보는 배포 제목 한 줄(`CareerConclusion.tsx:32`)과 접힌 답장 3개(`:26,38`)뿐이다. → CR-11
- **4-4 [확인] 결말은 답장 성향 비율로 정해지고 그 과정이 보이지 않는다.** `care`가 2/3 이상이면 동네, 1/3 이하면 작업실, 그 사이면 균형이다(`career-progress.ts:21-24`). → CR-12
- **4-5 [확인] 엔딩 뒤에 계속할 이유가 약하다.** 스튜디오는 같은 4파일을 고치고, 검사하고, 버전 5개까지 남기고, HTML로 내보낼 수 있다(`studio.ts:40-71`). 하지만 요청도 반응도 없고, "새 검사와 버전 기록에는 보상이 붙지 않습니다"라고 안내한다(`StudioWorkspace.tsx:53`). 남은 6개 의뢰는 결말이 고정된 뒤라(`career.ts:37`) 크레딧만 늘린다. 그 크레딧은 쓸 곳이 거의 없다(`docs/reviews/economy-2026-10-10.md` "Required 12-job route" 행: 전부 사도 4,010 cr 남음). Code Lab은 동네·고객과 따로 논다(`ChallengesHub.tsx:14`). → CR-13, CR-14
