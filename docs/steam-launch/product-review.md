# 0.11 제품·소개 문구 읽기 전용 검토

2026-10-09. 대상: `components/game/CodeLab.tsx`, `ChallengesHub.tsx`, `lib/game/code-lab.ts`, `docs/RELEASE-0.11-RC.md`, `app/about/content.ts`. 보상/재검사 주장 확인을 위해 `lib/game/code-lab-state.ts`와 `GameShell.tsx`의 연결도 읽었다. 브라우저를 실행하지 않았고 UI·런타임 소스는 수정하지 않았다. 인간 초보자·숙련자 플레이 검증을 대신하지 않는다.

후속 소스 재확인 결과, 최초 발견한 P2 보상 안내 누락과 P3 소개 문구 두 항목은 모두 해결되었다. 현재 이 검토 범위에서 열린 P1/P2 항목은 없다. 제품 기능/소개 주장의 소스 일치는 승인한다. 이는 Steam 출시 승인, 최소 사양 검증 또는 인간 초보자 검증 완료를 뜻하지 않는다.

## P2 — 반례 도전 보상 안내 누락 — 해결

**해결 확인:** 현재 `CodeLab.tsx:47`은 KO/EN/JA 모두 “첫 반례 성공 +30 cr · +15 XP · 문제당 한 번 지급”을 카드에 표시한다. `lab.audited.includes(job.id)`이면 요약에 지급 완료와 금액이 표시되어 저장 후 재방문에도 이미 받은 보상을 구분할 수 있다. 실제 상태의 일회성 지급 조건과 UI 설명이 일치한다. 아래는 최초 발견 기록으로 보존한다.

**최초 발견:** `CodeLab.tsx:47`의 반례 도전 카드와 성공 결과는 반례를 찾았다는 문구와 기록 체크만 표시했다. 첫 성공의 금액, XP, 일회성 보상 설명이 없었다. `code-lab-state.ts:31`은 실제로 +30크레딧/+15XP를 한 번 지급했다. `GameShell.tsx:70`은 lab 완료/반례에서 보상 소리를 내지만 lab에 대한 `setReward` 또는 `setMoment` 안내를 만들지 않았다.

소스상 재현 경로는 영수증 문제 완료 후 `{"price":500,"quantity":0}`으로 반례 검사다. 정상 결과0과 mutant 결과1500이 달라 처음에는30cr/15XP가 지급된다. 성공 문구만 읽으면 지급량과 반복 검사에 추가 보상이 없는 이유를 알 수 없다. 기존 크레딧 전역 표시의 변화만으로 추론해야 한다.

권장 수정은 도전 카드에 첫 반례 보상과 일회성 지급을 세 언어로 표시하고, 결과에서 이번에 지급했는지 이미 받은 기록인지 구분하는 것이다. 검사 결과 자체와 과거 획득 기록을 분리한다. UI 변경 권한은 메인 담당에 있어 이 검토에서는 수정하지 않았다.

## P3 — 소개 페이지의 최신 사실 반영 — 해결

**해결 확인:** 현재 `app/about/content.ts:58`, `107`, `156`의 세 Steam FAQ는 게임 미등록·실제 Steam 동작 미검증·출시일 미정으로 통일되었다. 영어`:109`는 “a limited JavaScript interpreter”, 일본어`:158`은 “限定されたJavaScriptインタープリタ”를 추가해 한국어`:60`과 기능 범위가 일치한다. 아래는 최초 발견 기록이다.

- `app/about/content.ts:58`, `107`, `156`은 Steam AppID/상점이 “확인되지 않았다”고 적는다. 이번 실제 계정 확인은 “이 게임 미등록·사용 가능 크레딧0”이다. 미출시/실환경 미검증이라는 결론은 같지만 최신 확인 사실로 통일할 수 있다.
- 한국어FAQ `:60`은 제한된 JavaScript 해석기를 언급하지만 영어`:109`와 일본어`:158`은 이전의 계산·설정 판정 중심 설명만 남아 있다. 전체 소개에는12함수 의뢰가 있어 이 FAQ도 같은 범위로 맞추면 좋다.

이 두 항목은 실제 없는 기능의 출시 완료를 주장하는 P1/P2 과장으로 분류하지 않는다.

## 요구에 대한 소스 확인

| 요구 | 확인 결과 |
| --- | --- |
| 초보자의 작은 수정부터 | 첫 영수증/할인 문제에 실제 소스의 연산자만 바꾸는 버튼. starter의 잘못된 결과와 기대 결과를 관찰하고 수정·검사로 이어짐 |
| 숙련자의 직접 문제 선택 | 12개 모든 항목을 직접 선택하며 선수 문제 잠금 없음. 직접 작업 선호면 코드 탭/전문가 표시를 초기 선택 |
| 잘못된 결과 재검사 | 기대/실제/입력·오류를 표시. 코드를 바꾸거나 입력 묶음을 바꾸면 proof 삭제; UI도 현재source/seed가 일치할 때만 통과 결과 표시 |
| 도움의 의무 여부 | 관찰·힌트·전체 예제는 테스트 실행의 선행 조건이 아님. 예제 적용 뒤에도 실제 실행으로 통과해야 완료 |
| 보상 차감·중복 지급 | 실패/도움에 차감 없음. 첫 완료와 반례는 각각 저장된 id로 중복 지급 방지. P2 지급 안내도 후속 수정으로 해결 |
| 함수를 직접 쓰는 경험 | 함수의 반환값을 각 입력의 기대 결과와 비교. 정답 문자열 비교를 하지 않음. 제한된JS라는 설명과 지원/미지원 문법이 UI에 있음 |
| 개념·주장 | 조건·반복·배열·집계·API응답·멱등성·원자성·캐시 퍼즐이 콘텐츠에 있음. 실제 서버/OS·자유JS·취업/실무 숙달/수시간 플레이를 약속하지 않음 |
| 출시·사람 검증 | 0.11 릴리스 문서는 Steam 미등록, 크레딧0, 다른AppID 사용 금지, 인간 결과 없음과0.10 영상의CodeLab 미포함을 명시 |

상점 초안은 제한된JavaScript 함수 퍼즐12개를 설명하며 최종 배포 빌드 확인 조건을 기록했다. 캡슐은 최종 제품명이 아직 미정인 상점 준비 단계이므로 승인 아트 기반 크기/배치 계획만 작성했다. 캡슐 이미지는 미생성이다.

## 후속 QA와 남은 출시 검증

메인 담당의 후속 보고에 따르면12개 문제와12개 반례를 세 언어에서 UI E2E로 확인했고, 초보자 UI 조작도 세 언어 smoke 검사를 통과했다. 이 검토자는 브라우저를 실행하거나 해당 E2E를 독립 재실행하지 않았다. 독립 확인한 범위는 위 소스 변경과 소개 주장의 일치다.

최종 보안 수정 후 메인 담당이 native 전체 플레이·저장 복구, 새 QA 패키지 실행, 전달용 오프라인 패키지와 renderer/main 파일 18개의 일치 및 보안 fuse 검사를 통과했다. 증거는 `output/steam-qa/native-report.json`, `packaged-report.json`, `output/art-qa/offline-package-report.json`이다. 별도 저사양 PC에서의 최소 사양 실측, 실제 코딩 비경험자의 이해·재미/학습 확인, 현지어 원어민 감수, 최종 제품명/아트 권리/캡슐 제작, 새 게임 AppID·depot·실제 Steam 업적/Cloud와 심사·공개는 여전히 남는다. 상점 문서는 해당 확인을 기다리는 초안 상태를 유지한다.
